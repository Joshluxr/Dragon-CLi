### When and How to Use Dragon

Here are a few examples of scenarios and tasks that Dragon excels at:

- Use voice to describe tasks for Dragon while on your commute, then pickup where it left off when you're back at your desk
- Delegate small or medium tasks from your TODOs so you can focus on higher-priority work
- Give Dragon backlog tasks that are hard to prioritize relative to other work
- Tag @terragon-labs on GitHub issues to assign larger, well-scoped work to Dragon
- Dragon works well for exploring or prototyping ambiguous solutions iteratively. Give an ambiguous prompt to see how it approaches the problem, then use [the Retry feature](/docs/tasks/retry) to refine the task
- If you know how to do a task but want to delegate it, describe the task to Dragon as if you were instructing another engineer
- Tasks that replicate existing patterns in your codebase work well. If you have an existing feature to replicate or adapt, send that task to Dragon
- Give Dragon tasks that can be verified with high confidence (e.g., if CI passes)
- If the task seems too large for one person, it may be too large for Dragon. Consider breaking it into smaller tasks, or asking Dragon to plan its own work first
